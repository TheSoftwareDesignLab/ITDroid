# What a hardcoded literal is used for.
#
# ITDroid follows every string literal of the app's smali to the first instruction that consumes
# it, and classifies that consumer with the rules below. Only text that reaches the user is worth
# translating; a log message, an exception message, an SQL fragment or a preference key must stay
# as written, or the app changes its behaviour.
#
# One rule per line:   <category>   <regular expression>
# The expression is searched in the callee as smali writes it, for example
#     Landroid/widget/TextView;->setText(Ljava/lang/CharSequence;)V
# Rules are tried from top to bottom and the first match wins, so put the specific ones first.
#
# Categories
#   ui           the text is shown (or spoken) to the user
#   log          the text goes to a log
#   exception    the text is the message of an exception
#   data         the text is a key, a query, a pattern, a path, a comparison operand...
#   compiler     plumbing emitted by the compiler (null checks, Compose source information)
#   builder      the text is appended to the object in the first argument (StringBuilder);
#                the object is followed to its toString() and beyond
#   passthrough  the call returns a text derived from this one (String.format, trim...);
#                the result is followed
#
# To add or override rules without rebuilding, put a file named hardcoded-consumers.txt in the
# settings folder: its rules are tried before these.
