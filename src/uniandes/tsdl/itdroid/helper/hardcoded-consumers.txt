# What a hardcoded literal is used for.
#
# ITDroid follows each smali string literal to the first instruction that consumes it and
# classifies that consumer with these rules. Only text that reaches the user is translated.
#
# One rule per line, a category then a regular expression searched in the callee as smali writes it.
# Rules are tried top to bottom and the first match wins, so specific ones go first.
#
# Categories
#   ui           shown or spoken to the user
#   composable   passed to an unknown composable, a bare identifier is not taken for text
#   log          goes to a log
#   exception    the message of an exception
#   data         a key, query, pattern, path or comparison operand
#   compiler     compiler plumbing such as null checks or Compose source information
#   builder      appended to the first argument object, which is followed to its toString()
#   passthrough  the call returns a text derived from this one, which is followed
#
# A hardcoded-consumers.txt file in the settings folder adds rules tried before these.
